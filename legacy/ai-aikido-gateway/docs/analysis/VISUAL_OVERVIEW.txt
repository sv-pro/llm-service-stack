KEY ARCHITECTURAL PATTERNS
───────────────────────────────────────────────────────────────────────────────

1. Plugin-First Architecture
   └─ BasePlugin + PluginPipeline decouples all concerns

2. Two-Tier Caching
   └─ L1 (Memory LRU) + L2 (SQLite) for speed + persistence

3. Context-Based Communication
   └─ RequestContext flows through pipeline, plugins share via metadata

4. Configuration-Driven
   └─ YAML config + dynamic class loading = runtime flexibility

5. Guard Rails
   └─ Fail fast with helpful errors when configuration missing

6. Request Normalization
   └─ Handle model-specific parameter differences transparently

7. Correlation IDs
   └─ UUID4 per request, traced through all async operations

8. Fallback Chains
   └─ Graceful degradation: gpt-4 → gpt-3.5-turbo on failure

9. API Key Pooling
   └─ Round-robin rotation for load balancing

10. Cost Tracking
    └─ Built into history plugin, independent of monitor plugin
